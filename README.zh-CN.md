# DSH 按需能力路由插件

保留已安装的能力，按需检索工具与读取参数，避免每轮请求携带全部工具定义。

支持中英文使用：英文直接匹配工具名称和描述，中文还可通过内置关键词扩展与自定义别名检索。DSH 原生插件信息页提供中英文介绍。检索效果取决于工具注册的元数据；当前采用关键词匹配，不会自动翻译所有工具。

适配版本：**DSH 0.2.2-rc.1、Node.js 24+**。DSH 的执行器接口尚不稳定，本插件明确固定兼容版本。

## 使用方式

```sh
dsh plugin --profile web add github:blankGMY/dsh-capability-router
```

重启 DSH 后，照常提出任务即可。模型通过三个固定入口工作：

插件必须复用宿主同一份 DSH 核心包实例，不能只保证版本号相同却另外安装一份。启动检查会在注册工具之前拒绝重复核心包，避免作用域检查失效；如遇该错误，应将插件的核心包依赖链接到宿主安装位置，不要关闭检查。

1. `capability_search`：检索当前会话有权使用的完整目录，支持中文别名、来源筛选和分页。
2. `capability_describe`：读取指定工具的完整参数和版本。
3. `capability_call`：校验参数后，通过 DSH 原执行管线调用真实工具。

无需先要求“启用某工具”，也无需另开一套 DSH。常用工具可以固定，固定名单不限制数量。新插件成功注册后会自动进入目录。

## 保留的行为

- 原权限、会话作用域和当前步骤准入集合继续生效；子代理不能冒用父代理身份。
- 图片、附件、结果元数据和结果处理仍走原管线，不统一转成字符串。
- 执行检查针对真实工具名，取消和并发规则继续生效。
- 使用过的工具不会全部永久提升为常驻定义。
- 参数错误或版本过期不会执行业务调用；写操作结果不明时不会自动重放。
- 记忆仍由现有记忆插件管理；技能正文仍通过原 `skill` 工具加载。

## 配置

在 profile 的 `cordis.patch.yml` 增加覆写，字段说明见 [英文文档](README.md)：

```yaml
- id: capability-router
  config:
    pinnedTools: [read, write, edit, glob, grep, bash, skill, memory_recall, memory_note]
    maxResults: 5
    maxParallel: 4
    aliases:
      mcp__example__inspect_binary: [二进制体检]
```

不配置 `pinnedTools` 时使用默认常用工具名单；显式配置会替换默认名单。空查询可以分页浏览全部可用工具。

## MCP 进程也按需启动

默认只接管工具定义的呈现，不争夺其他插件已有的连接。

若将某个服务器配置到本插件的 `servers` 中，可以进一步托管连接：缓存元数据后启动 DSH 不必启动该服务器，首次业务调用时再连接。首次冷缓存发现仍需连接服务器列出工具。只能移交连接所有权，不能让原客户端与本插件重复注册同一个服务器。

有状态的调试/GUI 服务默认不回收；只有明确设置 `stateless: true` 的服务可以空闲停止。卸载本插件时，需要把曾移交的服务器配置交回原客户端。

SDK 的输出校验器按工具首次实际调用时编译，避免 REA 等大型目录在加载时提前编译全部输出校验器；输出校验并未关闭。

## 边界

- PTC 和其他自定义执行器保持原样，当前版本不优化这些模式，不会为了优化而丢失代码执行能力。
- 当前是配置文件方式管理，没有独立的管理网页或未认证接口。
- 检索是关键词与中文别名排序，不承诺自然语言匹配百分之百准确。
- 完整参数、结果和历史仍占上下文；固定工具定义不代表全部请求始终命中缓存。
- 托管 MCP 客户端以工具调用为范围；资源、提示、采样、授权交互等需求应继续使用原客户端。目录变更后通过重连刷新元数据。
- 图片能否进入模型仍受 DSH 原生模型能力判断和附件存储规则约束。

## 验证

```sh
npm ci --ignore-scripts
npm test
npm run test:runtime
```

测试使用真实 DSH 注册表和执行管线。托管 MCP 测试使用本地协议服务，包含空闲回收、状态保持、版本变化和写操作不重放。
